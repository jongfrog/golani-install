# PROJECT GOLANI — 통합 개발 지시서

## 0. 프로젝트 개요 및 개발 원칙

프로젝트명: **golani (고라니)**

Minecraft Java Edition 서버를 간편하게 생성하고 관리할 수 있는 크로스 플랫폼 서버 관리 도구를 개발한다.

사용자는 복잡한 명령어를 직접 입력하지 않고 TUI 또는 Web UI를 통해 서버 생성, 실행, 중지, 재시작, 업데이트 및 설정 관리를 할 수 있어야 한다.

### 핵심 목표

- Minecraft Java Edition 서버 관리
- Vanilla 및 Paper 지원
- Rust 기반의 가볍고 빠른 프로그램
- 터미널 기반 TUI 제공
- 로컬 Web UI 제공
- Windows 10/11 우선 지원
- Linux 지원
- Java 자동 설치 및 버전 관리
- 서버 백그라운드 실행
- 서버 업데이트
- 단일 실행 파일 배포
- 설치 및 자체 업데이트 지원
- 모든 UI 한국어 제공

### 반드시 지켜야 할 개발 원칙

1. 아래 명세를 기준으로 개발한다.
2. 명세에 없는 기능을 임의로 추가하지 않는다.
3. 기존에 확정된 설계를 임의로 변경하지 않는다.
4. 설계를 변경해야 하는 상황이라면 변경 이유와 대안을 먼저 제시하고 승인을 받는다.
5. 실제 작동하는 코드를 작성한다. 화면만 구현하고 기능을 비워두지 않는다.
6. 각 마일스톤을 완료한 뒤 빌드와 테스트를 수행한다.
7. 현재 마일스톤이 완료되기 전에 다음 마일스톤으로 넘어가지 않는다.
8. 테스트하지 않은 기능을 완료했다고 보고하지 않는다.
9. 오류가 발생하면 원인을 분석하고 수정한 후 다시 테스트한다.
10. 불필요한 의존성 및 과도한 추상화를 피한다.
11. Windows에서 정상 작동하는 것을 우선적으로 보장한다.
12. 모든 사용자 안내와 UI 문구는 한국어로 작성한다.

# 1. 기술 스택

## 핵심 언어 및 라이브러리

| 분야 | 기술 |
|---|---|
| 메인 언어 | Rust |
| TUI | ratatui |
| 터미널 제어 | crossterm |
| 비동기 처리 | tokio |
| HTTP 요청 | reqwest + rustls |
| 직렬화 | serde / serde_json |
| 설정 파일 | toml |
| 해시 검증 | sha2 |
| 사용자 디렉터리 | dirs |
| 한글 출력 폭 계산 | unicode-width |
| 서버 관리 | Minecraft RCON |
| Web 서버 | axum |
| Web UI | HTML / CSS / JavaScript |

필요한 경우에만 추가 의존성을 사용한다.

## 프로그램 구조

- Rust Core: 모든 서버 관리 기능의 핵심 로직
- TUI: ratatui 기반 터미널 UI
- Web UI: axum 기반 로컬 웹 관리 화면
- Installer: 설치 및 업데이트 담당
- Java Manager: Java 버전 확인 및 설치
- Server Engine: 서버 실행 및 프로세스 관리
- Network Manager: 포트 및 방화벽 관리

TUI와 Web UI는 동일한 Core 로직을 사용해야 한다.

동일한 기능을 UI별로 별도로 구현하지 않는다.

# 2. 설치 및 실행 구조

설치 명령어

사용자가 다음 명령어로 설치할 수 있도록 한다.
윈도우
```cmd & powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm http://get-golani.kro.kr/install.ps1 | iex"
```
리눅스
``` cli
curl -fsSL http://get-golani.kro.kr/install.sh | bash
```
설치 후에는 다음 명령어로 실행한다.

```cmd & powershell
golani
```

설치 스크립트 주소:

`http://get-golani.kro.kr/install.ps1`
`http://get-golani.kro.kr/install.sh`

설치 스크립트는 다음 기능을 수행한다.

1. 운영체제 확인
2. CPU 아키텍처 확인
3. GitHub 최신 릴리스 확인
4. 사용자 환경에 맞는 바이너리 선택
5. 바이너리 다운로드
6. SHA-256 체크섬 검증
7. 설치 디렉터리에 파일 설치
8. 사용자 PATH 환경변수 등록
9. 설치 완료 안내

지원 대상:
- Windows x64
- Windows ARM64
- Linux x64
- Linux ARM64
- macOS ARM64
- macOS x64

실제 빌드 및 배포가 가능한 플랫폼부터 지원한다.

## 2-2. 설치 경로

Windows 설치 경로:

```text
%LOCALAPPDATA%\golani\
├── golani.exe
└── uninstall.exe
```

사용자 데이터 경로:

```text
%USERPROFILE%\.golani\
├── config.toml
├── golani.lock
├── java/
├── servers/
└── logs/
```

설치 파일과 사용자 데이터는 반드시 분리한다.

프로그램을 재설치하거나 업데이트하더라도 다음 데이터는 유지되어야 한다.

- 서버 데이터
- 서버 설정
- Java 설치 파일
- 사용자 설정

## 2-3. 자체 업데이트

다음 명령어를 지원한다.

```bash
golani update
```

기능:

1. 최신 GitHub 릴리스 조회
2. 현재 버전과 최신 버전 비교
3. 운영체제 및 아키텍처에 맞는 바이너리 확인
4. 다운로드
5. SHA-256 검증
6. 검증 완료 후 실행 파일 교체
7. 업데이트 결과 출력

기존 실행 파일은 새 파일의 다운로드와 검증이 완료되기 전까지 보존한다.

업데이트 도중 오류가 발생해도 기존 프로그램을 사용할 수 있어야 한다.

# 3. 데이터 및 설정 구조

## 3-1. 기본 서버 저장 위치

기본값:

```text
~/.golani/servers/
```

서버 저장 위치를 결정하는 유일한 기준은 다음 설정 파일이다.

```text
~/.golani/config.toml
```

설정 예시:

```toml
servers_dir = "C:/Users/User/.golani/servers"
```

서버 생성 마법사와 설정 화면은 동일한 `servers_dir` 값을 사용해야 한다.

서버 저장 위치를 변경하면 기존 서버 데이터를 새로운 위치로 이동하는 마이그레이션 기능을 제공한다.

이동 전 확인 대화상자를 표시하고 이동 중 오류가 발생하면 데이터가 유실되지 않도록 처리한다.

## 3-2. 서버 디렉터리 구조

```text
.golani/
├── config.toml
├── golani.lock
│
├── java/
│   └── temurin-21/
│
├── servers/
│   └── survival/
│       ├── .golani.json
│       ├── server.jar
│       ├── eula.txt
│       ├── server.properties
│       ├── world/
│       ├── plugins/
│       └── logs/
│           └── latest.log
│
└── logs/
```

## 3-3. 서버 메타데이터

각 서버 폴더에는 `.golani.json` 파일을 생성한다.

관리할 정보:

- 서버 이름
- 서버 유형
- Minecraft 버전
- Paper 빌드 정보
- RAM 설정
- 서버 포트
- 생성 날짜
- 마지막 실행 날짜
- 마지막 종료 상태
- Java 버전
- 기타 서버 관리에 필요한 메타데이터

실제 JSON 구조는 Rust 자료형과 호환되도록 설계한다.

# 4. 프로세스 및 잠금 관리

## 4-1. 전역 잠금

프로그램의 중복 실행을 방지하기 위해 다음 파일을 사용한다.

```text
~/.golani/golani.lock
```

파일에 PID를 기록한다.

이미 실행 중인 경우 다음 정보를 표시한다.

- 실행 중인 PID
- 잠금 상태
- 실행 중인 프로그램 정보

PID가 실제로 존재하지 않는다면 STALE 상태로 판단하고 자동 정리한다.

## 4-2. 서버별 잠금

각 서버도 별도의 잠금을 가진다.

동일한 서버가 중복 실행되지 않도록 한다.

프로세스가 비정상 종료되었을 경우 잠금 상태를 검사하고 복구할 수 있어야 한다.

# 5. 서버 이름 관리

서버 이름은 생성 시 중복 검사를 수행한다.

이름 변경 명령어:

```bash
golani rename <이름>
```

정책:

- 실행 중인 서버는 이름 변경 불가
- 서버 폴더명 변경
- `.golani.json`의 서버 이름 변경
- 월드의 `level-name`은 변경하지 않음
- 이름 변경 후 기존 데이터가 정상적으로 인식되어야 함

# 6. 서버 생성 마법사

서버 생성은 총 7단계로 구성한다.

## 1단계. 서버 이름

사용자가 서버 이름을 입력한다.

- 빈 이름 불가
- 중복 이름 불가
- 사용 가능한 문자 검사
- 추후 이름 변경 가능하다는 안내

## 2단계. 서버 종류 및 버전

지원 서버 종류:

- Vanilla
- Paper

Paper에는 권장 배지를 표시한다.

실제 API를 통해 버전 목록을 조회한다.

버전 목록에는 다음 정보를 표시한다.

- Minecraft 버전
- 서버 종류
- 최신 안정 빌드
- 업데이트가 오래된 버전 표시

존재하지 않는 버전이나 다운로드할 수 없는 버전을 선택할 수 없도록 한다.

## 3단계. 저장 위치

기본값은 `config.toml`에 설정된 `servers_dir`이다.

사용자가 저장 위치를 변경할 수 있다.

다음 경로는 경고한다.

- Downloads
- Desktop
- OneDrive 동기화 폴더

경고 후 계속 진행할지 y/N으로 확인한다.

## 4단계. RAM 설정

시스템 메모리를 확인하고 서버에 할당할 RAM을 선택한다.

정책:

- 시스템 RAM의 절반을 기본 상한으로 고려
- 최대 8GB
- 최소 2GB 권장 안내
- 사용 가능한 메모리 초과 시 경고
- 초과하더라도 사용자가 확인하면 진행 가능

서버 실행 시 `-Xms`, `-Xmx` 옵션을 적용한다.

## 5단계. 포트 설정

기본 포트:

```text
25565
```

포트가 이미 사용 중이라면 다음 사용 가능한 포트를 제안한다.

예시:

```text
25566
25567
25568
```

포트가 점유되어 있다면 점유 PID를 표시한다.

방화벽 설정도 확인한다.

## 6단계. 월드 설정

다음 설정을 입력할 수 있다.

- 게임 모드
- 난이도
- 시드
- MOTD

시드를 입력하지 않으면 랜덤 시드를 사용한다는 안내를 표시한다.

입력한 설정은 `server.properties`에 반영한다.

## 7단계. 최종 확인 및 생성

입력한 내용을 요약해서 보여준다.

확인 후 다음 작업을 수행한다.

1. 서버 디렉터리 생성
2. 서버 JAR 다운로드
3. SHA-256 검증
4. Java 버전 확인
5. 필요한 Java 자동 설치
6. `server.properties` 생성
7. `eula.txt` 생성
8. 서버 메타데이터 생성
9. 방화벽 규칙 설정 시도
10. 생성 완료 화면 표시

완료 화면에는 다음을 표시한다.

- 서버 이름
- 서버 종류
- Minecraft 버전
- RAM
- 포트
- 로컬 접속 주소 `127.0.0.1:<포트>`
- 로컬 네트워크 IP가 확인되면 해당 주소도 표시

# 7. Minecraft 서버 다운로드

## 7-1. Vanilla

공식 버전 manifest:

`https://piston-meta.mojang.com/mc/game/version_manifest_v2.json`

이 manifest를 통해 버전 정보를 조회한다.

해당 버전의 메타데이터에서 서버 다운로드 정보를 가져온다.

공식 SHA-1 등 제공되는 검증 정보를 확인하고, 프로젝트의 다운로드 보안 정책에 맞는 검증 방식을 적용한다.

공식 검증 정보가 없는 경우 검증이 완료된 것처럼 처리하지 않는다.

## 7-2. Paper

**반드시 최신 PaperMC Fill API v3를 사용한다.**

기존 PaperMC Downloads API v2는 2026년 7월 1일 종료되었으므로 사용하지 않는다.

다음 구버전 주소는 프로젝트 전체에서 제거한다.

```text
https://api.papermc.io/v2/projects/paper
```

### 공식 API

기본 주소:

```text
https://fill.papermc.io/v3/
```

Paper 버전 목록:

```http
GET https://fill.papermc.io/v3/projects/paper
```

특정 버전의 빌드 목록:

```http
GET https://fill.papermc.io/v3/projects/paper/versions/{version}/builds
```

예시:

```http
GET https://fill.papermc.io/v3/projects/paper/versions/1.21.8/builds
```

모든 요청에는 식별 가능한 User-Agent를 포함한다.

예시:

```text
User-Agent: golani/1.0.0 (https://golani.kro.kr)
```

### 빌드 선택

API에서 받은 빌드 목록 중 `channel`이 `STABLE`인 빌드만 기본 다운로드 대상으로 사용한다.

- STABLE: 기본 선택 대상
- EXPERIMENTAL: 기본 선택에서 제외

최신 안정 빌드를 기본으로 선택한다.

안정적인 빌드가 없으면 사용자에게 오류를 표시한다.

### 다운로드 정보

API 응답에서 다음 정보를 사용한다.

```text
downloads.server.default.url
downloads.server.default.name
downloads.server.default.checksums.sha256
downloads.server.default.size
```

주의사항:

- 다운로드 URL을 임의로 조합하지 않는다.
- API가 반환한 URL을 그대로 사용한다.
- API에서 제공한 SHA-256을 사용한다.
- SHA-256이 없으면 검증된 파일로 취급하지 않는다.
- 다운로드 크기 정보를 활용해 진행률을 표시한다.

### 다운로드 처리

1. 버전 목록 조회
2. 빌드 목록 조회
3. 최신 STABLE 빌드 선택
4. 다운로드 정보 확인
5. 임시 파일로 다운로드
6. 진행률 표시
7. 파일 크기 확인
8. SHA-256 검증
9. 검증 성공 시 `server.jar`로 이동

체크섬이 일치하지 않으면 임시 파일을 삭제하고 서버 생성 절차를 중단한다.

### 오류 처리

다음 상황을 처리한다.

- API 연결 실패
- HTTP 오류
- 잘못된 버전
- 안정 빌드 없음
- 다운로드 URL 누락
- SHA-256 누락
- 다운로드 중 연결 끊김
- 파일 크기 불일치
- SHA-256 불일치

공식 문서:

`https://docs.papermc.io/misc/downloads-service/`

# 8. Java 자동 설치 및 관리

Minecraft 버전에 따라 필요한 Java 버전을 자동으로 결정한다.

## 8-1. Java 버전 매핑

| Minecraft 버전 | Java 버전 |
|---|---:|
| 1.20.5 이상 | 21 |
| 1.18 ~ 1.20.4 | 17 |
| 1.17 | 16 |
| 1.16.5 이하 | 8 |

## 8-2. 배포판

Eclipse Temurin을 사용한다.

Adoptium API:

```text
https://api.adoptium.net/v3/assets/latest/<feature>/hotspot
```

## 8-3. 설치 경로

```text
~/.golani/java/temurin-<버전>/
```

예시:

```text
~/.golani/java/temurin-21/
```

## 8-4. 설치 정책

1. 시스템에 설치된 Java 확인
2. 호환되는 버전이 있으면 재사용
3. 없다면 자동 설치 안내
4. 사용자가 수동 Java 경로를 지정할 수 있도록 지원
5. 설치 전 디스크 용량 확인
6. 다운로드 진행률 표시
7. SHA-256 검증
8. 설치 완료 후 Java 실행 테스트

기존 Java를 불필요하게 다시 설치하지 않는다.

# 10. 서버 실행 엔진

## 10-1. 백그라운드 실행

서버는 `start` 명령어를 통해 detached 프로세스로 실행한다.

```bash
golani start <이름>
```

CLI를 종료하더라도 Minecraft 서버는 계속 실행되어야 한다.

운영체제별로 프로세스 분리 방식을 구현한다.

서버 프로세스의 stdout 및 stderr는 다음 파일에 기록한다.

```text
servers/<서버명>/logs/latest.log
```

## 10-2. RCON

서버 제어는 RCON을 사용한다.

RCON 설정:

- 주소: `127.0.0.1`
- 비밀번호: 서버 생성 시 자동 생성
- 비밀번호는 안전하게 생성
- `server.properties`에 자동 기입

RCON을 통해 서버의 상태와 명령을 제어한다.

## 10-3. 서버 중지

```bash
golani stop <이름>
```

다음 순서로 동작한다.

1. RCON 연결
2. `stop` 명령 전송
3. 최대 30초 대기
4. 정상 종료 확인
5. 30초 이후에도 종료되지 않으면 강제 종료

정상 종료를 우선한다.

## 10-4. 재시작

```bash
golani restart <이름>
```

정상 종료 후 다시 실행한다.

## 10-5. 콘솔 연결

```bash
golani attach <이름>
```

서버 콘솔에 연결한다.

- 서버 로그 실시간 출력
- 명령어 입력 및 전송
- ↑↓ 명령 히스토리
- ESC로 연결 해제
- 연결 해제 시 서버는 계속 실행

## 10-6. 로그 확인

```bash
golani logs <이름>
```

서버 로그를 실시간으로 출력한다.

# 12. 서버 상태 관리

TUI와 Web UI에서 동일한 상태를 표시한다.

상태는 총 6종이다.

| 표시 | 상태 | 색상 | 설명 |
|---|---|---|---|
| ● | 실행 중 | 초록 | 서버 정상 실행 |
| ◐ | 재시작 필요 | 노랑 | 변경 사항 적용을 위해 재시작 필요 |
| ○ | 정지 | 회색 | 서버가 정지된 상태 |
| ↑ | 업데이트 가능 | 파랑 | 서버 업데이트 가능 |
| ✖ | 오류 | 빨강 | 마지막 시작 실패 또는 오류 |

golani 자체 업데이트가 있다면 우측 상단에 별도의 업데이트 배지를 표시한다.

상태는 1초 간격으로 갱신한다.

메인 서버 목록에는 다음 정보를 표시한다.

- 상태 배지
- 서버 이름
- 서버 종류 및 버전
- 현재 상태
- IP 및 포트
- 마지막 실행 시각

ratatui와 crossterm을 사용한다.

## 17-1. 기본 화면 구조

```text
┌──────────────────────────────────────────┐
│ 헤더: 로고 및 현재 위치                  │
├──────────────────────────────────────────┤
│                                          │
│               메인 콘텐츠                │
│                                          │
├──────────────────────────────────────────┤
│ 푸터: 단축키 안내                        │
```

## 17-2. 부팅 화면

- 프로그램 초기화

- 잠금 확인
- 서버 데이터 확인

## 17-3. 메인 화면

서버 목록을 표시한다.

서버가 없으면 서버 생성 안내를 표시한다.

## 17-4. 서버 관리 메뉴

```text
1. 서버 시작 / 중지

4. 로그 확인

7. 서버 속성 편집
8. 서버 폴더 열기
9. 서버 삭제
```

각 메뉴는 실제 기능과 연결되어야 한다.

## 17-5. 키보드 조작

- ↑↓: 이동
- k/j: 이동
- Enter: 선택
- ESC: 뒤로 가기
- Q: 메인 화면에서 종료
- Ctrl+C: 종료 확인 모달

Ctrl+C를 누르면 다음 문구를 표시한다.

```text
UI만 닫습니다. 서버는 계속 실행됩니다 (y/N)
```

## 17-6. 콘솔 연결

- 실시간 로그 출력
- 명령어 입력
- Enter로 명령 전송
- ↑↓ 명령 히스토리
- ESC로 연결 해제
- 서버 프로세스는 계속 실행

## 17-7. 마법사 조작

ESC 입력 시 다음 단계로 처리한다.

- 이전 단계가 있다면 이전 단계로 이동
- 첫 단계라면 취소 여부 확인
- 진행 중인 다운로드 등 취소할 수 없는 작업은 별도 확인

## 17-8. 진행률 표시

다운로드 및 설치 작업은 진행률을 표시한다.

예시:

```text
████████░░ 80% 12.4MB/s
```

진행률을 알 수 없는 작업은 Spinner를 표시한다.

## 17-9. 터미널 호환성

- 한글 폭은 unicode-width로 계산
- 터미널 크기 최소 80x24
- 크기가 부족하면 안내 화면 표시
- 터미널 크기가 변경되면 UI 재배치

# 19. 네트워크 및 방화벽 관리

서버 외부 접속을 위해 OS 방화벽 규칙을 관리한다.

## 19-1. 기본 원칙

OS 방화벽 전체를 비활성화하지 않는다.

Minecraft 서버 포트의 TCP 인바운드 규칙만 허용한다.

지원 운영체제:

- Windows Defender Firewall
- Linux UFW
- Linux firewalld
- macOS 방화벽 상태 확인 및 안내

## 19-2. 방화벽 규칙 생성

서버 생성 또는 포트 변경 시 기존 규칙을 확인한다.

규칙이 없다면 자동 추가 여부를 사용자에게 질문한다.

규칙 이름:

```text
golani-<서버명>-<포트>
```

Windows에서는 관리자 권한이 필요할 수 있다.

권한이 없다면 사용자에게 수동 설정 방법을 안내한다.

## 19-3. 포트 변경

포트가 변경되면 다음을 수행한다.

1. 기존 golani 관리 규칙 확인
2. 해당 서버의 기존 규칙 제거
3. 새 포트 규칙 생성

golani가 생성하지 않은 기존 사용자 규칙은 수정하거나 삭제하지 않는다.

## 19-4. 서버 삭제

서버 삭제 시 해당 서버가 만든 방화벽 규칙을 제거한다.

서버를 정지하는 경우에는 방화벽 규칙을 유지한다.

## 19-5. 오류 처리

방화벽 관리 권한이 없거나 규칙 생성에 실패하더라도 서버 실행 자체를 막지 않는다.

오류와 수동 설정 방법을 안내한다.

## 19-6. 외부 접속 진단

외부 접속이 되지 않을 경우 다음 항목을 확인한다.

1. 서버 프로세스 실행 여부
2. 서버 포트 리스닝 여부
3. OS 방화벽 규칙
4. 공유기 포트포워딩
5. 공인 IP 확인
6. CGNAT 여부

OS 방화벽 규칙을 추가하는 것만으로 공유기 NAT, 포트포워딩, ISP CGNAT 문제가 해결되는 것은 아니다.

이 차이를 사용자에게 명확히 안내한다.

# 20. 보안 및 다운로드 정책

모든 다운로드 파일은 무결성을 검증한다.

대상:

- Minecraft 서버 JAR
- Paper 서버 JAR
- Java
- golani 자체 업데이트 바이너리
- 설치 프로그램에서 내려받는 바이너리

## 공통 정책

1. 다운로드 전에 공식 출처 확인
2. 임시 파일로 다운로드
3. 공식 체크섬 확보
4. SHA-256 계산
5. 체크섬 비교
6. 검증 성공 시에만 최종 파일로 이동

공식 체크섬이 제공되지 않는 경우 임의로 검증 완료 처리하지 않는다.

해결 방법이 필요하면 해당 상황과 대안을 보고한다.

다운로드 중 연결이 끊기거나 파일이 손상되더라도 기존 정상 파일이 유지되어야 한다.

설정 및 비밀번호 등 민감한 데이터는 불필요하게 로그에 출력하지 않는다.

## 최종 개발 지시

이 문서를 프로젝트의 전체 개발 기준으로 사용한다.

기존 프로젝트 파일을 먼저 분석하고 현재 구현 상태를 확인한다.

이미 구현된 기능은 불필요하게 다시 작성하지 않는다.

기능이 명세와 다르게 구현되어 있다면 차이점을 먼저 파악하고 수정한다.

각 마일스톤을 순서대로 진행하고 완료 후 반드시 다음 내용을 보고한다.

1. 구현한 기능
2. 변경 및 생성한 파일
3. 실제 실행한 테스트
4. 테스트 결과
5. 발견된 문제
6. 다음 마일스톤 계획

테스트가 실패하면 다음 마일스톤으로 넘어가지 않는다.

**중요: 명세에 없는 기능을 임의로 추가하지 말고, 확정된 설계를 임의로 변경하지 않는다.**
